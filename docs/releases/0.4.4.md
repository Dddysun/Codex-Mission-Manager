# V0.4.4 — Long snapshot reception / 超长状态接收

## 修复 / Fix

实际只读诊断捕获到 207,053,198 字节、约 197 MiB 的状态帧，超过 0.4.3 的 128 MiB 上限，导致共享读取连接断开，并使其他聊天显示连接待恢复。这是客户端状态数据接收限制，不是已确认的模型上下文超限；也不是检查时默认暂停。

Read-only diagnostics observed a 207,053,198-byte snapshot, approximately 197 MiB, exceeding the 128 MiB limit in 0.4.3. The shared reader disconnected and other chats showed connection errors. This is a desktop-state reception limit, not confirmed model context exhaustion or a routine global pause.

接收上限提高到有界的 256 MiB；超限仍在分配正文前拒绝。每次新快照采样成功或失败后，尽力取消本工具对该聊天的状态订阅；不改变其他客户端的订阅或聊天执行。取消订阅写入最多等待 1 秒，失败不重复发送聊天指令。

The receive limit is now bounded at 256 MiB. Larger headers are rejected before body allocation. After each snapshot attempt, this tool releases its own subscription without altering another client's subscription or chat execution. Cleanup writes have a one-second deadline; failures never replay chat instructions.

保留 0.4.3 的监控窗口、规则版本保护、提前发布真实额度时间戳和原生深浅色修复。Mac、Windows 共用本次后台修复；品牌组件仍为 1.3.0。

Monitoring-window choice, revision protection, early quota publication with actual timestamps, and native theme fixes from 0.4.3 remain. Both platforms share this backend fix; brand remains 1.3.0.

## 验证与限制 / Validation and limits

隔离回归使用 200 MiB 模拟历史正文，验证解析后的状态、后续其他聊天请求和订阅退出；原有超限拒绝、断线清理和重连检查保留。发行预览使用模拟数据，不能作为真实低额度暂停和恢复的验收。

The isolated regression uses 200 MiB of synthetic history and checks normalized state, subsequent requests for another chat, and subscription cleanup. Existing oversized-frame rejection, disconnection cleanup and reconnection checks remain. Release previews are synthetic and do not establish live quota pause/recovery acceptance.

256 MiB 仍是有限上限，解析大帧会增加瞬时内存和处理耗时；本次并未实现流式解析或服务器端按字段裁剪。更大的长会话仍可能需要后续采集优化。临时签名、未公证／未签名和版本敏感的本机控制限制继续适用。

256 MiB is still finite. Large frames increase transient memory and processing time; this release does not implement streaming JSON parsing or server-side field selection. Longer histories may require further collection improvements. Existing signing, notarization and version-sensitive local-control limitations remain.
