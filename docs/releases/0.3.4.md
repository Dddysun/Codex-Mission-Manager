# V0.3.4 public preview / 公开预览

Activity on Mac and Windows now has a source dropdown: **All records / User actions / Automatic processes**. It groups the latest loaded records for easier review while preserving stored history and task-control behavior.

Mac 与 Windows 的操作记录增加 **全部记录／用户操作／自动进程** 来源下拉筛选，方便查看最近载入的记录，保留原有历史及任务控制行为。

## Changes / 更新

- **Three source filters:** All records is the default. User actions and Automatic processes display the corresponding subset. / **三项来源筛选：**默认显示全部记录，也可选择用户操作或自动进程。
- **Consistent classification:** the backend supplies the event origin to both interfaces. Older records are classified from existing readable evidence without rewriting the original stored entries. / **统一分类：**后台向两平台提供记录来源；旧记录按已有可读证据兼容判断，不回写原始记录。
- **Stable selection:** background refresh, language changes, and appearance changes retain the current filter. An empty-result message explains when the loaded range contains no matching entries. / **保留选择：**后台刷新、语言及外观切换保留当前筛选；载入范围内没有匹配项时显示提示。
- **Updated previews:** six native screenshots cover both platforms and four page types, highlighting the new Activity dropdown. All screenshots use synthetic data. / **更新预览：**六张原生截图覆盖两平台及四类页面，重点展示操作记录下拉框，全部使用示例数据。

## Reading the filters / 筛选范围与含义

**User actions** includes recorded user-operated switches, saved rules, saved or cancelled schedules, Run now requests and their results, and user-initiated quota resets inferred from credit evidence. **Automatic processes** includes monitoring-triggered pauses and resumptions, automatic execution when a schedule becomes due, and quota observations generated by monitoring, including scheduled and independent service recovery.

**用户操作**包括已记录的用户开关、规则保存、预约保存或取消、“立刻执行”的请求及结果，以及依据权益证据推断的用户主动额度重置。**自动进程**包括监测触发的暂停和续接、预约到期自动执行，以及监测生成的额度记录，包括官方正常周期与独立恢复。

The source describes how the recorded operation occurred. A saved schedule belongs to User actions; its later automatic execution belongs to Automatic processes. Existing quota-reset source labels remain evidence-based inferences, with `official_reason` null. Filtering a user-reset record does not establish a confirmed human action. See the [V0.3.3 attribution limits](https://github.com/Dddysun/Codex-Mission-Manager/blob/main/docs/releases/0.3.3.md).

来源按记录对应操作的发生方式划分：保存预约属于用户操作，之后到期自动执行属于自动进程。既有额度重置来源仍是基于证据的推断，`official_reason` 保持空值；将用户重置记录归入筛选，并不证明已确认人工操作。具体边界见 [V0.3.3 来源判断说明](https://github.com/Dddysun/Codex-Mission-Manager/blob/main/docs/releases/0.3.3.md)。

The filter applies locally to the **latest 200 records in total** returned to the interface. It does not retrieve 200 records per category or search the complete database. An empty filter result means that there is no match in the loaded range; it does not establish that the category has never occurred. Filtering preserves records, tasks, permissions, schedules, and quota-recovery rules. Existing records and quota-history baselines are retained during upgrade.

筛选在界面本地作用于已返回的**最近 200 条总记录**，不会为每一类各取 200 条，也不搜索完整数据库。没有匹配项只表示当前载入范围没有该类记录，不代表历史上从未发生。筛选保留原有记录、任务、许可、预约和额度恢复规则；升级保留既有记录与额度历史基线。

## Packages and upgrade / 安装包与升级

Choose a V0.3.4 preview from [Releases](https://github.com/Dddysun/Codex-Mission-Manager/releases). Each immutable `v0.3.4-preview.N` tag identifies its source commit and package set:

- `Codex-Mission-Manager-0.3.4-arm64-preview.dmg` — Apple Silicon, macOS 14+.
- `Codex-Mission-Manager-0.3.4-windows-x64-setup.exe` — current-user installation, Windows 10 build 19041+, x64, .NET Framework 4.8+.
- `Codex-Mission-Manager-0.3.4-windows-x64-preview.zip` — portable Windows package.

Both platforms bundle the backend and a pinned Python runtime. Quit the previous version before upgrading. Application data remains in its separate local directory. See the [user guide](https://github.com/Dddysun/Codex-Mission-Manager/blob/main/docs/USER_GUIDE.md).

两平台均附带后端及固定 Python 环境。升级前退出旧版，应用数据继续保存在独立本机目录；使用方法见[使用指南](https://github.com/Dddysun/Codex-Mission-Manager/blob/main/docs/USER_GUIDE.md)。

## Validation and limits / 验证与限制

Isolated checks cover event-origin classification, older-record compatibility, source filtering, selection retention, empty results, and unchanged stored history. Mac runs the full backend and packaging-host suites. Windows retains limited smoke checks and native offline validation, including the Activity filter self-test. Native fixture images show the new dropdown without starting a production backend or sending messages. Package, lifecycle, input-layout, and gallery gates remain in place. The attached receipts describe the actual result of the selected preview; skipped or failed checks are not passes.

隔离检查覆盖记录来源分类、旧记录兼容、来源筛选、选项保留、空结果及原记录保持。Mac 执行完整后端与打包宿主测试；Windows 保留有限冒烟及原生离线检查，并包含操作记录筛选自检。原生示例截图展示新下拉框，不启动生产后台、不发送消息；安装包、退出生命周期、输入框布局及图库检查继续保留。实际结果以所选预览附带回执为准，跳过或失败不计通过。

Real-client sending, quota-triggered pause/recovery, actual credit-use transitions, keyboard/IME interaction, system notifications, startup, and lock/display-off/sleep/lid behavior retain their existing manual acceptance requirements. The Mac preview is ad-hoc signed and unnotarized; Windows is unsigned. Existing client compatibility limits and closed-lid-operation limits continue to apply.

真实客户端发送、额度暂停续接、实际权益使用变化、真人键盘与输入法、系统通知、登录启动，以及锁屏、熄屏、睡眠和合盖行为继续保留既有人工验收要求。Mac 为临时签名且未公证，Windows 未签名；既有客户端兼容范围及合盖运行限制继续适用。
