# V0.4.2 — Runtime resource integrity / 运行资源完整性

## 本次修复

修复应用运行后在程序包内新增 Python 字节码缓存，导致 Mac 签名完整性检查失败的问题。Mac、Windows 原生启动器及后台子进程显式禁止生成此类缓存；保留隔离运行模式。

新增可写应用副本检查：导入后台和此前在实际使用中才加载的标准库模块，启动隔离的后台自检子进程，确认资源未变，再验证 Mac 签名。此检查不连接真实聊天、不读取私人运行数据。

通信超时现在包含写入等待；广播写入和桌面连接关闭也有时间上限。对端停止接收数据时，采集循环可以退出本次失败操作。发送结果不确定时仍不会自动重发。

任务保存和榨汁开关使用写事务，防止后台旧状态或同时修改不同聊天偏好覆盖用户刚提交的关闭操作。接管回调再次检查撤销；许可、修订号、偏好和接管意图一起提交或回滚。

聊天排序直接查询已有目录字典，减少重复遍历。额度校验拒绝 NaN、无穷和超大整数；可选权益异常时间被忽略。本机 HTTP 接口限制 16 个工作线程和 5 秒 I/O 空闲，拒绝请求时有界丢弃正文，改善 Windows 错误回执。

大快照等待使用配置的有限传输预算，保留短诊断连接的最低快照窗口。新增延迟快照及超时测试；接收上限仍为 128 MiB。

界面和品牌组件保持现有设计。预览使用本版本构建与模拟数据；修复属于运行与打包行为，不能从静态截图证明。

## Fix

Prevent Python from adding bytecode caches inside the application after launch, which invalidated the Mac resource seal. Both native launchers and owned subprocesses explicitly disable bytecode writes while retaining isolated mode.

Verification now exercises cold imports and an isolated child on a writable application copy, checks that resources are unchanged, and verifies the Mac signature again. It does not connect to live chats or read private runtime data.

Request deadlines now include write backpressure. Broadcast writes and desktop connection shutdown are bounded as well, allowing collection to recover from a peer that stops accepting data. Uncertain sends are still never replayed automatically.

Write transactions protect user revocations from stale task saves and concurrent preference updates. Task permissions, revisions, preferences and adoption intents commit or roll back together; late adoption callbacks recheck cancellation.

Chat sorting uses direct catalog lookups. Quota validation rejects nonfinite and overflowing values and ignores invalid optional credit timestamps. The local HTTP service limits workers to 16 and idle socket I/O to five seconds. Bounded draining of rejected bodies preserves error responses on Windows.

Large snapshots use the configured finite transport budget, retaining the minimum snapshot window for short diagnostics. Delayed-snapshot and timeout regressions cover the change; the frame limit remains 128 MiB.

The native interface and brand component retain their existing design. Screenshots use this version and synthetic data; static images do not demonstrate the runtime fix.

This branch is a development candidate. Publication, installation, and hands-on acceptance require their own release and validation records. A source fix or passing offline check does not mean a running installation has been upgraded.

The transaction, HTTP, input and snapshot changes added during the 2026-10-29 review have not been repackaged. Earlier 0.4.2 candidate packages do not prove their deployment. See the [code review](../reviews/2026-10-29-code-review.md) for remaining local-data encryption and application-instance authentication work.

Mac 预览仍为临时签名、未公证；Windows 预览仍未签名。真实额度恢复、Windows 托盘交互和合盖运行限制继续适用。

Mac previews remain ad-hoc signed and unnotarized; Windows previews remain unsigned. Live quota recovery, Windows tray interaction, and closed-lid limitations still apply.
