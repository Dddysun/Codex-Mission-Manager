# V0.4.5 — Fresh quota after long collection / 长采集后的额度复核

## 修复 / Fix

实机短时观察中，修复大帧后的控制连接保持可用、聊天错误为零，但额度缓存年龄仍曾达到 96 秒，超过默认 90 秒有效期。长采集结束后再等待正常间隔，会短暂触发待核验；这不等于用户暂停了榨汁。

A short real-device observation after the large-frame fix kept control available with no chat errors, but quota age reached 96 seconds against the default 90-second budget. Long collection followed by the normal wait could briefly trigger verification; global juicing was not manually paused.

本版在本轮额度年龄与下一正常等待接近有效期时，额外调用一次真实额度读取，再发布结果。只有服务回复后才推进采样时间；记录同样经过额度历史审计。短轮保持一次读取，不修改用户保存的 30／10／5 秒设置。复核失败仍进入未知状态并暂缓自动续接。

When current sample age plus the next normal wait approaches the freshness budget, this release reads quota again before publishing the completed cycle. Only a service reply advances observation time; both samples are audited. Short cycles retain one read and saved intervals remain unchanged. Failed closing checks stay unknown and withhold automatic resumption.

保留监控窗口选择、Pro 默认周额度、256 MiB 有界接收及快照订阅释放。并未实现并行采集或流式 JSON 解析；极慢采集与真实通信失败仍可能需要等待核验。

Monitoring-window choice, weekly defaults for Pro, bounded 256 MiB reception and subscription cleanup remain. Collection is not parallelized and JSON is not streamed; extremely slow collection and genuine failures can still require verification.

## 验证 / Validation

增加接近有效期的边界检查，以及模拟 70 秒聊天采集的实际循环测试：确认第二次服务回复提供新时间戳，且第二次读取超时时不会把旧采样当成成功。保留 200 MiB 状态帧、超限拒绝、重连、规则和双平台原生检查。发行预览使用模拟数据，不发送或中断真实聊天。

New checks exercise the freshness boundary and an actual loop with 70 seconds of simulated collection: the second reply supplies a new timestamp, while its timeout cannot turn old data into a successful refresh. The 200 MiB frame, size rejection, reconnection, rule and native-platform checks remain. Release previews use synthetic data and do not send to or interrupt real chats.

安装与真实低额度恢复仍需分别验收。Mac 临时签名、未公证；Windows 未签名；控制通道仍依赖版本适配。

Installation and live low-quota recovery require separate acceptance. Mac remains ad-hoc signed and unnotarized; Windows is unsigned; the control channel remains version-adapted.
