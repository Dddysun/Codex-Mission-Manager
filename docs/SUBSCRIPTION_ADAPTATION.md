# V0.2.1 订阅与额度窗口适配

本版使用服务实际返回的数据决定额度显示和控制行为，不根据套餐名称推算额度数值或固定倍数。当前配置的额度桶为 `codex`；不将它等同普通 ChatGPT 所有模型的额度。

## 识别规则

Free、Go、Plus、Pro、Business、Enterprise、Edu 及未知套餐名称均保留接口实际返回的套餐信息。额度桶中的 `planType` 优先于缓存的账号套餐。套餐升级无需改变账号身份命名空间。

- 300 分钟窗口显示为五小时额度。
- 10080 分钟窗口显示为周额度。
- 其他有效时长显示为实际分钟、小时或天数，不将 primary / secondary 的位置当作窗口类型。
- 仅返回周窗口时，界面只显示周额度，注明未提供五小时窗口；没有虚构的五小时刷新时间。
- 有效窗口中的 0% 是真实耗尽；缺失、非法或过期数据不能转换成 0%、100% 或无限额度。

OpenAI 的[官方额度接口文档](https://learn.chatgpt.com/docs/app-server)定义了窗口时长、使用比例与刷新时间；[官方订阅说明](https://learn.chatgpt.com/docs/pricing)指出当前 Pro 可能没有五小时限额。实现仍以实时响应为依据，不把文档中的套餐描述当成自动执行授权。

## 额度状态和控制

1. **有计量窗口（metered）：**校验所有返回窗口。周窗口耗尽时暂停；五小时和其他窗口按剩余不高于10%暂停、至少20%才允许恢复。恢复仍须服务许可、账号与消息一致以及既有重复检查。
2. **无固定窗口、服务明确允许（service_only）：**仅在 primary 与 secondary 都明确返回 null，且 ordinaryUsageAllowed 明确为 true 时成立。可按实际服务许可执行；不显示百分比或虚构刷新时间。
3. **未知（unknown）：**缺少必要信息或校验失败时，明确显示不可确认，禁止自动发送。套餐叫 Pro 不能改变该判断。
4. **服务阻止使用：**服务封锁、花费控制或明确拒绝使用时禁止发送；仍可登记或执行符合条件的额度保护暂停。

本版不购买额度、兑换重置次数或改变账号计费方式。使用许可不明确时不自动尝试付费路径。

## 预约与旧记录

新预约优先绑定实际返回的五小时窗口；没有五小时窗口时，选择其他非周窗口中时长最短的窗口；仅有周额度时绑定周窗口。界面展示预约目标及实际刷新时间。没有可用的固定窗口时，停用新的额度窗口预约，并保留“立刻执行”入口及后端核验。

预约记录保存窗口身份、时长与刷新时间。窗口位置交换不会误发；原窗口消失或结构发生变化时需要重新确认。V0.2 只有标量刷新时间的旧预约仍按五小时窗口解释，不会改当周预约。取消已有预约始终保留。

同一账号从 Plus 切换到 Pro 不再被当作不同账号。V0.2 旧命名空间只有在能用当前账号和工作区身份重建并精确匹配时才迁移；保留任务许可、人工保持、预约状态、指令、版本与请求标识。真实换账号或工作区不会通过此迁移混用任务。

## 验收边界

自动化回归使用模拟套餐和服务响应，不能替代各套餐真实账号的长期实测。仍需兼容桌面客户端；私有桌面 IPC、无外屏合盖及普通 ChatGPT/云端聊天控制不在本次修改范围。公开安装包仍为无 Developer ID 公证的预览版。

具体测试数量、原生界面渲染与安装包验证结果见 `validation.json` 和发行说明。
