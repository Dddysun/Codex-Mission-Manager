# TokenMax 原生界面短视频素材

为 0.4.2 preview.13 / 品牌组件 1.3.0 制作的十组中文介绍镜头。直接复用 Mac 的 SwiftUI / AppKit 视图；没有重画一套网页界面。每组导出横屏 2560×1600 和竖屏 1080×1920，30 fps、H.264、静音。竖屏附标题、重点区域缓慢放大和演示标识；横屏保留完整界面，附小型演示标识。输出不含桌面、其他应用、真实账号或聊天内容。

这些是隔离进程中渲染的原生界面演示，不是从已安装应用采集的真实运行录像，也不能作为真实暂停、恢复或官方额度事件的验收证据。余额、时间、任务、预约和结果全部来自静态模拟数据，等待过程已压缩。恢复原因在原生界面中仍标注“推断”。不生成音轨，不提供会员价格或额度比例的事实证明。

## 使用

需要 Apple Silicon Mac、Xcode Command Line Tools、Python 3、FFmpeg（含 libx264）与 ffprobe。在仓库根目录执行：

```sh
python3 -B design/media/tiktok-recorder/build.py --build /tmp/tokenmax-media-build
python3 -B design/media/tiktok-recorder/scenes.py /tmp/tokenmax-media-plan.json
/tmp/tokenmax-media-build/TokenMaxMediaRecorder /tmp/tokenmax-media-plan.json /tmp/tokenmax-media-output
python3 -B design/media/tiktok-recorder/finalize.py /tmp/tokenmax-media-plan.json /tmp/tokenmax-media-output
```

使用新的输出目录；已有视频不会被覆盖。可以传 `--scene 04` 只生成预约镜头，或增加 `--preview` 仅生成该镜头的原生检查帧。完整收尾检查需要十组视频齐全。`finalize.py` 将视频索引移至文件头、生成 40 秒总览、逐帧解码检查全部视频，并写出 SHA-256 与机器可读清单。

## 镜头

1. 额度与任务总览（10 秒）：五小时窗口、周额度和任务状态。
2. 低额度自动暂停（12 秒）：14% → 11% → 8%，任务从执行到等待恢复。
3. 额度恢复自动续接（12 秒）：8% → 86%，复核后接续已有任务。
4. 提前写好预约指令（16 秒）：逐字输入、保存为一次性预约。
5. 第二天检查执行结果（8 秒）：展示模拟结果，保留人工验收提示。
6. 额度恢复历史记录（12 秒）：前后余额、时间、自动进程筛选和来源推断。
7. 暂停与恢复运行规则（8 秒）：暂停 / 恢复阈值与复核、采集间隔。
8. 深浅外观与主题色（10 秒）：浅色蓝、深色蓝、深色紫、浅色绿。
9. 菜单面板与后台运行（8 秒）：原生菜单面板，提示维持正常运行条件。
10. 新版闪电 Logo 特写（14 秒）：原生分叉放电及独立两秒呼吸。

唯一镜头总长 110 秒；两种画幅分别一套。总览按各镜头四秒串联，供选片，不能替代完整演示。

## 隔离方式与边界

`scenes.py` 只读仓库中的公开测试 fixture，替换为虚构任务和保留域名 `example.invalid`。不读已安装应用的数据目录、Codex 历史、账户或钥匙串。

`build.py` 在临时构建目录复制原生源文件，禁用应用入口与后台启动方法，启用原有中文测试模式，使用模拟时钟，给视图增加初始导航 / 筛选参数。不会修改产品源码、安装包、已安装应用或系统时间。Logo 几何、状态、分叉和两秒呼吸仍使用生产实现，只替换时间输入。界面的开关使用原生绘制；离屏视图可能采用非活动窗口的控件外观。

`Recorder.swift` 的窗口不展示、不激活，不请求屏幕录制权限，不发送全局键鼠事件。输入动画只编辑演示进程自己的 `NSTextView`；每帧检查没有后台进程、服务地址或状态目录。没有调用暂停、续接或发送聊天指令的方法。

工具仅用于此处生成的可信演示计划。生成视频和构建缓存应留在仓库外；不要将真实数据、用户下载目录或整个工作区上传。产品版本与发布流程保持独立，修改本目录不触发安装包发布。
